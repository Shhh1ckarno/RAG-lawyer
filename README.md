# RAG-lawyer
Консольный помощник для **предварительной уголовно-правовой квалификации по Уголовному кодексу РФ**. Пользователь описывает ситуацию обычными словами, а система выдает результат по структуре:
1) **Cтатьи УК РФ**, которые подходят с точностью до части и пунктов.
2) **Предусмотренное наказание**.
3) **Смягчающие обстоятельства** из ст. 61 УК РФ, которые стоит проверить.
4) Каких фактов не хватает для точной квалификации.

## Принцип работы
# Первый этап
Так как векторные базы данных работают по принципу косинусной близости, то ссылки внутри статьи на другие статьи приводят к ошибкам, поэтому **текст УК РФ был переписан** с целью убрать все ссылки для наилучшей точности. На первом этапе происходит подготовка базы данных ChromaDB.
**Подготовка базы данных будет только на первом этапе!**
# Второй этап
Цикл обработки графом.

**Описание ситуации пользователем** -> **Аналитик** (*переводит текст на юридический язык*) -> **Compare** (*сравнение с базой данных ChromaDB и выбор ближайших статей*) -> **Lawyer** (*отбор статей, полученных на прошлом этапе*) -> **Judge** (*выносит вердикт на основе описания ситуации и отобранных статей*).

## Установка зависимостей
Нужен Python 3.10+ и запущенный OpenAI-совместимый сервер с чат-моделью и эмбеддинг-моделью (например, LM Studio с включённым сервером на порту 1234 как в этом проекте).

`pip install openai chromadb langgraph pydantic python-dotenv`
## Запуск
1. Подготовка базы (один раз)

Если parts_rewritten.jsonl уже есть в репозитории, шаги parts.py можно пропустить и сразу выполнить индексацию.
2.

`python parts.py` - переписывание всех частей.

`python parts.py --limit 20` - переписывание 20 частей.

`python parts.py --fix` - повторно переписать части, где остались ссылки или потерялись пункты.

`python rag.py` - построить векторную базу в chroma_db/.
3.

`python main.py` - запуск кода.

4. **Описывайте ситуацию** и получайте ответ.

## Оценка качества
`uk_eval_dataset.json` содержит 100 ситуаций (23 easy, 49 medium, 28 hard) по шести категориям: 
1. Преступления против собственности. 
2. Против жизни и здоровья.
3. ДТП.
4. Наркотики.
5. должностные преступления и сложные случаи.

Для каждой указаны ожидаемые статьи (часть и пункты), допустимые альтернативы, «ловушки» — правдоподобные, но неверные квалификации — и ожидаемые смягчающие обстоятельства.

## Результаты на небольшой подвыборке
Использована была модель **Qwen-3.5-9B** с режимом thinking у юриста и аналитика, иначе результаты заметно хуже.

Выборка из 18 случаев по 6 на каждую сложность, поэтому результат может быть не репрезантативен.
1. **Нужная статья среди кандидатов поиска (retrieval):** 0.94.
2. **Нужная статья в ответе юриста (recall):** 0.94, на сложных 0.83.
3. **Полнота пунктов:** 0.79
4. **Точность по частям внутри статьи (precision):** 1.00.
5. **Попаданий в ловушку :** 0. 
## Файл .env
Параметры .env файла

`BASE_URL` - API к модели.

`LLM_MODEL` - название LLM для подключения по API.

`EMBED_MODEL` - название эмбединг модели для подключения по API.

`CHUNK_SIZE` - максимальная длина чанка (не используетс так как статья делится на части и подпункты).

`OVERLAP` - количество токенов, которые пересекаются или же накладываются друг на друга.
